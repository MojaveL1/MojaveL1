01the problem

Anything recorded today can be read later.

A public chain is a permanent record. Someone can copy it now, keep it on a disk, and run the maths on it years from now when the hardware is cheap enough. That turns every payment you make today into a note that opens itself later.

Privacy coins answered the first half of that: they hid the sender, the receiver and the amount using elliptic curves. The second half is the harder one. Elliptic curve privacy is exactly the kind that a large quantum computer undoes, and the record is already written.

Mojave is built so that what is private today stays private after quantum. Payment detection moved to a lattice first, because that is the step that ties a payment to a person, and spells out how spend proofs follow.

02the machinery

Six pieces, and each one replaces something a public chain gives away.

senderring of 16

Ring signatures

Each input signs alongside 15 decoys drawn from the chain, weighted toward recent outputs so the ring looks like a real spend. One of the 16 is yours. The proof never says which.

replaces a public sender field
receiverone time keys

Stealth outputs

Nothing is paid to an address. Every payment lands at a key derived for that payment alone, so two payments to the same wallet share nothing an observer can match.

replaces a reusable address
amountpedersen

Hidden amounts

The value travels as a Pedersen commitment with a 48 bit range proof. Inputs and outputs balance as curve points, so nobody can mint coins from a negative amount.

replaces a public amount
quantumml kem 768

Lattice receive

A quantum address carries an ML-KEM-768 public key. The sender encapsulates a fresh secret for every payment and the ciphertext rides with the output. Only the receiver can open it.

replaces elliptic curve diffie hellman
double spendkey images

Key images

One output always produces the same key image, so a second spend is refused, yet nothing on chain links that image back to the output it came from.

replaces a public spent flag
consensusargon2id

Memory hard work

Argon2id with 8 MiB per hash. Ordinary CPUs stay competitive, and no one signs a block, so there is no validator key to forge or lean on.

replaces validator signatures
03one payment

What actually happens when you send.

01

Share an address

The receiver hands over a quantum address: a spend key, a view key and an ML-KEM-768 public key. It is about 1,700 characters, so wallets copy it whole rather than ask anyone to type it.

02

Derive a one time address

Your wallet encapsulates a shared secret to that lattice key and turns it into a key used once. Nobody else can compute the same key from the chain, then or later.

03

Seal the amount

The amount becomes a commitment, encrypted to the receiver and backed by a range proof. The chain sees a point, not a number.

04

Sign inside a ring

The wallet picks 15 decoys, builds one signature across all 16 members and publishes a key image. All of it runs in your browser, on your keys.

05

Mine and scan

The node checks the signature, the range proofs, the balance and the key image. Miners seal it, and every wallet tries its keys on the new output. One of them opens.

04where it stands

Honest about the half that is not quantum safe yet.

Receiving survives quantum today. Spending still uses elliptic curve ring signatures, and Faraday is the upgrade that moves them to hash based proofs over the whole chain, which is why it is the next milestone rather than a marketing slide.

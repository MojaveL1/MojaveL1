01the ring

Your input hides among fifteen others.

An input does not point at a single coin. It points at sixteen outputs, one of which it can spend. A two row MLSAG signature over ristretto255 proves that the signer owns one of the sixteen one time keys, and that their commitment matches the pseudo input, without indicating which.

Decoys are not drawn evenly. Real spends land in recent blocks, so a ring spread flat across the chain would itself be evidence. Maturity is enforced too: an output younger than three blocks cannot be spent, and cannot be used as cover either, so the newest blocks are never in a ring.

The same signature publishes a key image, which is how the chain rejects a second spend:

I = x · Hp(P)   // one output, one image, forever
02the receiver

An address is never paid twice.

Each payment lands on a key that exists for that payment only. The sender derives it from a secret shared with the receiver, so only the two of them can compute it.

P = Hs(ss, i) · G + A

On a classic address the shared secret comes from elliptic curve Diffie Hellman. On a quantum address it comes from ML-KEM-768 encapsulation, and a 1,088 byte ciphertext travels with the output so the receiver can recover the secret years later.

To everyone else the chain holds two unrelated keys. There is no address to cluster, no balance to total up, no history to follow.

03the amount

Values balance as points, not numbers.

An amount is a Pedersen commitment. The blinding factor and the value are encrypted to the receiver, so a wallet can open its own outputs and nobody else can open anything.

C = x · G + v · H

Each output carries a 48 bit range proof: forty eight bit commitments, each with a two member ring signature proving it opens to zero or to a power of two. That is what stops a negative amount from minting coins.

A transaction is valid when the pseudo inputs equal the outputs plus the fee, checked as curve points. The node never learns any of the numbers involved.

04the quantum gap

Receiving is lattice based today. Spending is next.

Ring signatures, key images and derived secrets all rest on the discrete log problem, which is the problem a large quantum computer solves. Hiding the receiver behind a lattice key is the part that matters first, because that is the step that connects a payment to a person.

todayml kem 768

Detection

The receiver's wallet decapsulates a lattice ciphertext to find its payment. No elliptic curve step for the receiver, and the ciphertext is stored with the output.

faradayspends

Proofs move to hashes

Spend proofs become hash based, so the last elliptic curve dependency in a transaction goes, and the anonymity set becomes the whole chain instead of sixteen outputs.

mainnetfrom block 1

Same chain

Faraday ships as an upgrade to this chain. Each wallet migrates its coins once, automatically. No new coin, no new address format to relearn.

05verify

Do not take the node's word for it.

Every transaction page in the explorer has a verify button. Your browser fetches the transaction and its ring members from /api/rawtx/:id and runs the same verifyTx the node runs: every ring signature, every range proof, and the balance of commitments.

That is the reason the code is public and small enough to read. Cryptography comes from the audited noble libraries: ristretto255 and SHA3 from @noble/curves and @noble/hashes, ML-KEM-768 from @noble/post-quantum, and Argon2id from Node itself.

what is not finished

This is a testnet served by a single node, and spending still depends on elliptic curves. No independent audit of this code has been published, so treat the privacy claims as testable, not as assured.
